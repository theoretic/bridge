- The one failure, `page/edit/?id=1073` (template `case`), returned 500 under both themes with

  The PageTableNext field templates include their own dependencies through single-quoted

  rewrites both quote styles. On the rebuilt sandbox the page renders under both themes and only
  reports a missing image (assets/files are not copied into sandboxes).
- Noted in passing by that review: `PageTableNext::hookFileFailed` catches `\Exception` only, so
  a PHP `Error` inside a field template gives a 500 rather than an inline notice.
- Differences removed during this run, all theme-own: Uikit's per-field theme settings
  (`themeOffset`, `themeColor`, `themeBorder`, `themeInputSize`, `_adminTheme*`), Font Awesome
  version (Bridge now uses 6.7.2 like Uikit, icon selects match: 1896 options), `ui-widget` /
  `ui-state-*` classes that Uikit strips, 1-point column spacing, counter ids of anonymous
  `InputfieldMarkup`, user id and name on the profile screen.

The last four sandboxes were added after the first pass to cover the modules installed only there
(FieldtypeImageReference, SeoNeo, WireWall, MarkupActivityLog, ProcessHannaCode, ProcessTranslatePage,
JsonNativeField). Their runs used the runner with the `InputfieldIs*` normalisation (txm had reported

uncovered module, MarkupSimpleNavigation, is front-end markup with no admin UI.

Every site-identical failure is one of: a missing original image (sandboxes do not copy `assets/files`), editing the admin `page` page itself (template restriction), an SVG file-validator warning. None involves the theme.

Theme fixes forced by this run, all now in AdminThemeBridge: Font Awesome 6.7.2 icon set (icon pickers), `inputfieldColumnWidthSpacing = 0` and `InputfieldWrapper useColumnWidth = 2` (row breaks identical to Uikit). A wrong first attempt at the last one (`$config->InputfieldWrapper(...)` is not callable on this core unless the key already exists) broke the theme init mid-run and cost one rerun.

Module coverage (`conformance/modules.txt`): 46 of 47 locally installed third-party modules are on at least one sandboxed site and were rendered on those screens; MarkupSimpleNavigation (odnaco only, front-end markup) is the one left; the Pro set is postponed (ADR 0009); the directory "top set" is not installed anywhere yet.

Decision: gate 1 passes for the community modules installed locally. Zero theme-caused differences and zero theme-caused failures across 950 screens on nine sites. Browser pass complete except the drag-move of a page in the tree. Open before the public release of phase 1: the directory top set (TracyDebugger, RockMigrations, RockFrontend, AdminOnSteroids; needs the modules fetched into a sandbox), and Pro modules when ADR 0009 is revisited.

Site bugs found on the way, filed as separate tasks, not Bridge's: testfly's sitemap save hook references `SiteIndex` which the admin never autoloads; odnaco's SaveUID includes a `site/shared/uid.php` that does not exist.

contract.
